# Export the real retained Flower Net to the independent Regina oracle

The input is the actual retained Flower implementation and its stable material
IDs. The result is a labelled triangle quotient of each actual drawing cache,
not a shape guessed from positions. Material_node and material_edge_midpoint
are distinct roles; two coincident folded vertices must never be welded just
because their XYZ values match. The export has bounded file-output effects.

Type sketch before source: triangle_count : Number → Number doubles a quad
count. The full boundary needs labelled material incidence, render-parent
triangles, barycentric subdivision, orientability and boundary reports.
Output must preserve Net identity and keep drawing diagonals out of material
adjacency. A diagram's subdivision is not insertion of crochet stitches.

acquisition attempt. Invoke the unchanged one-step entrypoint from
isomorphisms/Idric e8b9173ab2d840ef0cf212698ea2fee97bd9e807. The actual probe
result: invoked that entrypoint on net-topology.idric, exit 2 before type checking,

compile only through the declared source-pinned ICK lane. Regina remains a
host-only foreign oracle; its C++ runtime is not added to Flower Android.

The first Idriç requirement is compiler acquisition and native execution of
the checked value 2048; this example does not infer a language defect before
that boundary. Full mesh export additionally needs bounded collections and
file output. No generated-C backend or stock-compiler consumer fallback is used.
