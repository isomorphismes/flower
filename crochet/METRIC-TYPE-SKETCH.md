SUN FLOWER-METRIC-01 / FLOWER-REALIZATION-01

The implementation target is Flower's native C/ICK boundary, using the real
Mostow ICK source convention (`←`, `÷`) and the owned ICK compiler. There is no
new Python, JavaScript, generated-C or stock-compiler fallback. A future Idriç
consumer should preserve the semantic roles below rather than aliasing every
value to an unqualified vector or distance. This is native implementation,
not a claim that an Idriç port has been compiled. The ledger's concrete Idriç
attempt and compiler-acquisition failure are preserved in
`examples/autogenerated/stitch-count/`; this consumer extends that same native
boundary rather than inventing a second unexecuted Idriç attempt.

Values and domains: immutable counted-stitch ledger; synthetic gauge with
positive circumferential width and row height; a bounded smooth reference
metric; local developed edge length; Euclidean realization; flat triangle
approximation; vertex angle defect and boundary turning; material marker ID.

Operations: ledger plus an explicitly chosen gauge/interpolant defines the
reference metric; metric plus local material coordinates computes an edge
length; metric plus a declared realization family computes an R3 point;
reference triangle plus realized triangle computes two singular stretches.
Only output writers perform I/O. Failed calculations leave outputs unchanged.

Invariants: ledger IDs, parent links, seams and stitch count are not determined
by coordinates. Metric radius and curvature have distinct types conceptually.
Negative-curvature polar radius is sinh(sqrt(kappa)*r)/sqrt(kappa), whereas the
synthetic crochet annulus radius is R0*exp(k*r); these are separate families.
The latter's rows are horocycles, not distance circles about a disk centre.
Graph hops, intended edge length, R3 chord and camera distance remain separate.

Required native facilities: finite IEEE binary64 arithmetic without fast-math,
sqrt/hypot/asinh/sinh/cosh/log/exp/trigonometry, bounded heap allocation and
stdio for the executable evidence artifact. Invalid, degenerate, range,
capacity and I/O statuses are observable. Current C structs are forgeable,
therefore operations validate them rather than assuming phantom-type proofs.

An Idriç implementation would first need checked quantity/metric constructors
and foreign or native finite transcendental operations that preserve these
statuses. This file does not invent unsupported Idriç syntax or represent the
native implementation as an Idriç compiler result.
